# Implementation Report — Transaction Ledger redesign

**Branch:** `feat/redesign-transactions-ledger` · **PR:** [#197](https://github.com/AlexDevsTheWeb/myfinance/pull/197) · **Commits:** `734062a`, `91886f5` · **Status:** shipped

## Context

`/transactions` used the two-column layout from
[[wiki/features/transaction-layout-improvement/transaction-layout-improvement]]:
filters and a pie chart on the left, table on the right. No period presets, no
account filter, no export, no row duplicate, 20-row page.

The trigger was a Stitch prototype dropped in `docs/raw/2026-10-UI-refactor/`
(`2026-10-26-prompt.md` + `.html`). The prompt was written against an older
codebase: it targets MUI v5, `src/` paths, a `useTransactionStore` that does not
exist, and a `DashboardLayout` component that no longer exists. The referenced
screenshot (`Screenshot 2026-10-26 alle 12.48.55.png`) was not in the repository.

Three scope questions were resolved with the user before coding:

| Question | Decision |
|---|---|
| Replace `/transactions` or add `/ledger`? | Replace the page content; route and sidebar entry unchanged |
| Row actions? | Edit, **Duplicate**, Delete — Duplicate required a new store action |
| Header buttons? | Both real: CSV export and column toggles |

## Decisions

1. **Metrics ignore text/category filters.** Summary cards are computed over
   period + account + card only, so typing in the search box does not make the
   KPI cards jump. The toolbar's "showing X of Y" already communicates the
   filtered count.
2. **Inflow trend vs previous equal-length window.** No month-over-month
   assumption; the badge hides when the previous window is empty rather than
   showing a meaningless +100%.
3. **Recurring card is a monthly equivalent.** Yearly templates are divided by
   12 so the card reads as a cost rate, not a list total. The next-charge date is
   computed from `dayOfMonth` / `monthOfYear`, and ended templates are excluded.
4. **Duplicate is a fresh one-off.** It copies description, category,
   subcategory, amount, type, account and card, dates it today, and **drops**
   `recurringLinkId`, `consumption`, `readingDateStart/End`. Copying a recurring
   link would create a second generated instance; copying meter readings would
   attach the wrong consumption to a new utility transaction.
5. **CSV uses `;` + BOM + decimal comma.** Italian Excel treats `,` as the
   decimal separator. The escape function takes the active separator, so `42,50`
   is not quoted in a `;`-delimited file.
6. **Column visibility in `localStorage`** (`balancr.ledger.columns`) rather than
   a Firestore field — it is a display preference, not user data, and adding a
   schema field for it would have required a migration.
7. **Page index clamped during render**, not in an effect. The first lint run
   flagged `react-hooks/set-state-in-effect`; deriving `currentPage` from
   `min(page, lastPage)` avoids the cascading render instead of suppressing the
   rule.
8. **Client-side pagination.** Transaction volumes do not justify server-side
   paging, and the store already syncs the full set.

## Deviations

| Prototype | Implementation | Agreed? |
|---|---|---|
| MUI v5, Tailwind classes | MUI v9, `sx` + existing theme tokens | Constraint of the codebase |
| Rebuilds sidebar and top bar | Shell reused from `components/layout/Layout.tsx`; only page content built | Judgement — rebuilding the shell would duplicate the app frame |
| Global search in the top bar | Search moved into the filter toolbar | Judgement — this app's shell has no global search, so removing it would be a functional regression |
| Type badges: Ricorrente Mensile / Bimestrale / PAC Automatico / Una Tantum | Ricorrente / Una Tantum | Judgement — the model has `recurringLinkId` and `frequency` only; the other two would need invented data |
| Account column with "SDD Diretto" / "Bonifico In" labels | Account name + card name | Judgement — no payment-method field exists |
| Screenshot reference | Absent; HTML export used instead | Unavoidable |

```bash
python3 docs/scripts/okf_validate.py
# 99 pages valid, indexes complete, 0 warnings
```

Two defects were caught by the checks during the work, not after merge:

- **CSV quoting** — the first escape rule quoted `42,50` because it contained a
  comma, which is only correct when the separator *is* a comma. The function now
  takes the separator and the unit test locks it.
- **Cascading render** — clamping the page inside `useEffect` tripped the
  `react-hooks/set-state-in-effect` rule; fixed by deriving the page during
  render rather than suppressing the lint.

## Not verified / deferred

- **No pixel comparison against the prototype.** The screenshot was unavailable
  and the repository has no visual-diff tooling. Fidelity is reasoned from the
  Tailwind classes; a manual pass at 1280px and 375px is still owed.
- **No real-browser interaction test** — there is no E2E harness, so row menus,
  the column toggle and the CSV download were exercised only through unit tests
  and the production build.
- **Deferred by design:** no changes to the dashboard table (it keeps its own
  simpler layout), no server-side pagination, no new Firestore fields.
