# Implementation Report — Settings page redesign

**Branch:** `feat/redesign-settings-page` · **PR:** [#201](https://github.com/AlexDevsTheWeb/myfinance/pull/201) · **Status:** shipped

## Context

The settings page was a 1,362-line `ConfigPage` with seven tabs across the top,
four different dialogs for entity creation, and hardcoded `rgba(255,255,255,…)`
surfaces. The prompt asked for a Stitch layout: a "Parametri Sistema"
sub-sidebar, drawer-based creation, and dark theme-token styling.

The page already contained all seven sections and their CRUD logic, so this was a
layout and interaction refactor — not new functionality. Two decisions were
confirmed with the user before starting:

| Question | Decision |
|---|---|
| Route and component | Keep `/config`, rename the component to `SettingsPage` |
| Drawer scope | All four flows (account, card, category, recurring) via a shared shell |

The prompt's screenshot (`Screenshot_2026-10-26_alle_16.48.26.png`) was not in
the repository; the work follows the written spec and the HTML export.

## Changes

| Area | What changed |
|---|---|
| `pages/SettingsPage.tsx` | Renamed from `ConfigPage`; new header, grid layout, theme-token surfaces, regional block, mono figures |
| `components/settings/SettingsNav.tsx` | New — rail/pills from one section list, with counts |
| `components/settings/EntityDrawer.tsx` | New — shared right slide-over |
| `components/settings/categoryColor.ts` | New — deterministic colour from the category name |
| `components/settings/settings.styles.ts` | New — surface and monospaced-figure helpers |
| `components/shared/form.styles.ts` | Moved from `transactions/drawer.styles.ts`; consumed by the transaction drawer and settings |
| `locales/{it,en}.json` | `settings.*` keys, card/account drawer titles |
| `App.tsx` | Imports `SettingsPage`; the route stays `/config` |

## Decisions

1. **One section list, two layouts.** The desktop rail and the mobile pills both
   render `SettingsSection[]`. Duplicating the list would have let a section
   exist in one and not the other.
2. **Route untouched.** Renaming `/config` would break bookmarks and every wiki
   reference for no user-visible gain; only the component name follows the
   prompt.
3. **Shared drawer, not four bespoke ones.** `EntityDrawer` owns the chrome and
   accessibility; each flow owns only its fields. The recurring form keeps its
   own layout because it is a different beast (it reuses `TransactionForm`).
4. **`keepMounted={false}`.** Without it the recurring template form mounted on
   page load and read the stores while closed.
5. **Form styles moved to `shared/`.** The drawer had `drawer.styles.ts`; settings
   needed the same input treatment. Moving it to `components/shared/form.styles.ts`
   keeps one definition instead of two near-identical `sx` objects.
6. **Deterministic colour dot.** `ICategory` has no colour. Deriving it from the
   name is stable, device-independent and needs no migration — unlike adding a
   persisted field for decoration.
7. **Currency disabled, date format previewed.** The app is EUR-only and the date
   format follows the language. Rendering selectors that cannot change anything
   would be a lie; a disabled field with the current value is honest.
8. **Baseline Growth Rate omitted.** No consumer exists in the projection engine.
   Adding the field would create a setting that silently does nothing.

## Not verified / deferred

- **No browser pass.** Neither the sticky rail, the mobile pills, nor any of the
  four drawers was opened in a browser; the repo has no E2E harness.
- **The recurring template drawer still uses filled inputs.** It wraps the shared
  `TransactionForm`, whose field styling predates the form-styles module.
  Restyling it would destabilise the template editor; left as a follow-up.
- **No pixel comparison** — the referenced screenshot is absent.
- Deferred by design: baseline growth rate, category icons/reordering, currency
  switching, broker drawer.
