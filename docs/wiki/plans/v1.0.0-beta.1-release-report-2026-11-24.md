# Implementation Report — SemVer 1.0 switch and v1.0.0-beta.1 milestone

**Branch:** `chore/semver-1-0-adoption` · **PR:** pending · **Status:** partially-shipped

## Context

The raw document (`raw/2026-11-24-versioning/2026-11-24-versioning.md`) asked for
two things: tag `development` as `v1.0.0-beta.1` with a GitHub Release, and
produce an inventory of all open issues for milestone planning.

The tag request collided with the documented release model. Releases are
year-prefixed CalVer (`v2026.16.0`, the last one), produced by
`standard-version` inside `version-bump.yml` only after a `development → main`
merge. `main` was 53 commits behind `development`, so none of the work named in
the requested changelog was deployed. Tagging `development` directly would also
have made a SemVer prerelease the baseline for the next automatic bump.

The user chose to switch the project to SemVer, keep the artifacts in the wiki
bundle, and generate the changelog from the commits since `v2026.16.0` rather
than copying the document verbatim.

## Decisions

- **SemVer over CalVer** — recorded in [[wiki/decisions/semver-1-0-adoption]].
  The deciding argument is expressiveness at the beta boundary: a year-prefixed
  number cannot name a prerelease line or promise format stability. Rejected:
  keeping CalVer (no beta line), and a hybrid date+SemVer scheme
  (`standard-version` understands one version).
- **Tag deferred to post-merge** — a tag must point at a commit that exists on
  `development`. Tagging the feature branch would leave the tag off
  `development`; tagging before the switch merges would miss the switch. The
  plan page holds the exact three commands, so the remaining step is mechanical.
- **Changelog from commits** — `git log v2026.16.0..development` and the merged
  PR list, not the document's summary. This surfaced three shipped changes the
  document omitted: Dashboard (#195), marketing site (#194), and monorepo
  Phase 1 (#191).
- **Wiki bundle over `docs/reports/`** — `docs/reports/` is outside the OKF
  bundle, so the validator would not see it and the index would not link it.
  The plan and query pages are indexed and validated.

## Deviations

1. **No tag and no GitHub Release in this change.** Both are post-merge steps,
   documented in the plan page with runnable commands. Consequence: this PR
   produces no version on GitHub by itself.
2. **The document's changelog was corrected, not copied.** It lists the ledger,
   settings and utilities work but omits the Dashboard, the marketing site and
   the monorepo move. It also gives the shell colour as `#0B0E14`; the actual
   theme token is `#0B0F17` (`apps/web/src/theme/theme.ts:57`). The release notes
   use the verified value.
3. **The release-detection regex was fixed although not requested.** Under
   CalVer a missed breaking bump was survivable; under SemVer it is the difference
   between 1.x and 2.x. The fix is two characters of regex plus a comment.
4. **Three issues are flagged for closing but were not closed** — #127, #137 and
   #123. Closing is a maintainer action and would be a remote side effect the
   user did not request.
5. **The dashboard page was refreshed** because the release notes depend on it
   and it had been stale since June. Only verified facts from PR #195 were added.
6. **The Settings sub-sidebar width was corrected** from 240px to 220px. The
   feature page contradicted itself (title and table said 240, the implementation
   note and `SettingsNav.tsx` say 220). The release notes use the code value.

## Not verified / deferred

- **No tag pushed and no GitHub Release created** — deferred to post-merge by
  design; see the plan's *Post-merge steps*.
- **No production deploy.** Nothing has been deployed since `v2026.16.0`. A tag
  on `development` is not reachable from `main`, so the pipeline does not run.
- **`standard-version` was not executed for real.** Running it writes
  `CHANGELOG.md` and creates a tag, which would pollute this branch. The
  prerelease behaviour was verified with `semver.inc` only.
- **`version-bump.yml` was not exercised in GitHub Actions.** The regex was
  tested locally with the same `grep -E` invocation; the workflow itself needs a
  merge to `main` to run.
- **In-app version display not checked in a browser.** `npx tsc -b` does not run
  `prebuild`; `npm run build` did, and `apps/web/src/version.ts` now contains
  `1.0.0-beta.1`.
- **Issue closures pending** — #127, #137, #123 are flagged in the inventory.
