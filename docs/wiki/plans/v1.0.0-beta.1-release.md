# Plan: v1.0.0-beta.1

Status: `in-progress` — version switch in PR, tag and Release pending the merge
Priority: **high**

## Goal

Mark the current `development` state as the first SemVer milestone,
**`v1.0.0-beta.1`**, with release notes that match what actually shipped since
`v2026.16.0`, and hand the next milestone a triaged issue backlog.

## Release notes (GitHub body)

**v1.0.0-beta.1 — Executive Dark UI & Core Modules Refactor**

First SemVer milestone. It establishes the Swiss-Tech / Executive Dark design
system, the unified transaction drawer, the rebuilt Settings page, the dense
transaction ledger, the new Dashboard, and the utilities & consumption
analytics engine.

### 🚀 Features & modules

- **Utilities & consumption (#202)** — one page for electricity, gas and water:
  period and utility filters, four KPI cards (spend, volume, weighted unit rate
  in €/kWh · €/SMC · €/m³, fixed-vs-energy share), a dual-axis spend/volume
  chart with a bill tooltip, a 12-month YoY overlay, and a dense bill ledger
  with search, sort, pagination, duplicate, delete and CSV export.
- **Settings page (#201)** — `ConfigPage` became `SettingsPage`: a 220px
  sub-sidebar on desktop and scrollable pills on mobile, one shared 480px entity
  drawer for accounts, categories, subcategories and cards, draft save/reset,
  masked IBAN tiles, and a regional/currency formatting preview.
- **Transaction ledger (#197)** — `/transactions` rebuilt as a full-width
  ledger: three KPI cards, a single-row filter toolbar, a dense sortable table
  with row actions, CSV export, column toggles and client-side pagination.
- **Slide-over transaction drawer (#199, #200)** — a 480px right drawer
  replaces the dialog, with three type tabs, a hero amount field, progressive
  disclosure for expenses/income/transfers, and utility-supplier, meter and
  fixed/energy quota fields. One route-aware `useNewTransaction()` entry point
  backs the TopBar CTA and the mobile header `+`.
- **Dashboard (#195)** — rebuilt from the Stitch prototype: KPI metrics row,
  bento widgets, charts row, master-detail calendar section, and a dashboard
  TopBar with search and create actions.
- **Marketing site (#194)** — the Balancr landing page ships as an isolated
  `apps/website` workspace with its own Firebase Hosting target.

### 🎨 Executive Dark design system

- Shell `#0B0F17`, cards `#131B2E`, nested surfaces `#0E1524`, borders
  `#1E293B`, cyan/emerald/rose/amber accents, and `JetBrains Mono` for monetary
  figures and dates (`apps/web/src/theme/theme.ts`).
- One content frame and a route-aware global TopBar across every non-dashboard
  page; page titles live in the TopBar, not in the content.

### 🧱 Infrastructure & data

- **Monorepo Phase 1 (#191, #192)** — npm workspaces; the app lives in
  `apps/web`; `envDir` points at the repo root so the env file keeps working.
- **Optional utility fields (#202)** — `ITransaction` gained optional
  `utilityType`, `fixedFee`, `energyFee`, `provider`, `meterId`. Additive only:
  no migration, and bills without `utilityType` are classified from
  category/subcategory keywords.
- **Release pipeline** — the version scheme moves from CalVer to SemVer, and
  breaking-change detection now recognises `feat!:` / `fix(scope)!:`.

### 📚 Docs & process

- Knowledge bundle reorganized into `docs/{raw,wiki}` with an OKF validator.
- Implementation reports are now mandatory for every PR (#198).

### ⚠️ Known gaps

- **This tag is a development checkpoint.** Nothing has been deployed to
  production since `v2026.16.0`; the next `development → main` merge with a
  releasing commit performs the deploy.
- 26 open issues remain, triaged in the
  [open-issues inventory](https://github.com/AlexDevsTheWeb/myfinance/blob/development/docs/wiki/queries/open-issues-inventory-2026-11-24.md).

## Post-merge steps

Run these **after** this PR merges and `development` is up to date. The tag must
point at the merge commit, not at a feature-branch commit.

```bash
git checkout development
git pull origin development

# 1. Verify nothing regressed at the tagged commit.
npx tsc -b
npm test

# 2. Annotated tag.
git tag -a v1.0.0-beta.1 \
  -m "Release v1.0.0-beta.1: Executive Dark UI, Settings, Dashboard, Utilities"

# 3. Push the tag (this does not trigger a deploy).
git push origin v1.0.0-beta.1

# 4. Draft GitHub Release from the notes section above.
awk '/^## Release notes \(GitHub body\)/{f=1;next} f&&/^## /{exit} f' \
  docs/wiki/plans/v1.0.0-beta.1-release.md > /tmp/v1.0.0-beta.1.md
gh release create v1.0.0-beta.1 --draft \
  --title "v1.0.0-beta.1 — Executive Dark UI & Core Modules Refactor" \
  --notes-file /tmp/v1.0.0-beta.1.md
```

Publish the draft only after checking the notes against the tag. `main` will
pick the tag up as its baseline on the next release merge.
