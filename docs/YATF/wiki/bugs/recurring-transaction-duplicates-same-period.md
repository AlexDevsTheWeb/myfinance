# Bug: checkRecurring Generates Duplicate Transactions (Race Condition)

Status: **fixed**
Severity: **critical**

## Symptom

After the sub-collection write fix, each page load creates new copies of all recurring-generated transactions with fresh `crypto.randomUUID()` IDs. Over 5+ reloads, 5 copies of the same transaction accumulate (same date, description, amount, `recurringLinkId`).

## Reproduction

1. Have any recurring template (monthly or yearly)
2. Reload the page 5 times
3. Each reload generates new duplicates with different document IDs

Verified with `window.__finance.getState().transactions`:
- 487 total, 345 unique (date|desc|amount)
- `x5` duplicates for recurring txs like Google One, Netflix, etc.
- All 5 copies share the **same** `recurringLinkId` (meaning they were generated by `checkRecurring`, not manually added)

## Root Cause

**Timing race condition** in `src/hooks/useSyncFinance.ts` between Firestore `onSnapshot` listeners:

1. UserDoc `onSnapshot` fires → calls `checkRecurring()` (guarded by `hasCheckedRecurring`)
2. Sub-collection `onSnapshot` may not have fired yet → `state.transactions = []`
3. `existsInPeriod` always returns `false` (empty array) → generates new transactions for **every** period
4. `set()` updates store with newly generated txs
5. Sub-collection `onSnapshot` fires → `setAll({ transactions: sorted })` overwrites store with sub-collection data (doesn't include newly generated txs)
6. Batch write reads `getState().transactions` → gets overwritten data → writes nothing
7. Generated txs **lost** — never persisted
8. Next page load: same cycle → new `crypto.randomUUID()` IDs accumulate

Before PR #145 (sub-collection write fix), these were invisible — written to dead `UserDoc.transactions` field.

## Fix

### Fix 1 — Timing guard (`src/hooks/useSyncFinance.ts`)
`checkRecurring()` only runs when **both** data sources are loaded:

```typescript
// UserDoc onSnapshot
if (!hasCheckedRecurring.current && subColLoaded.current) {
  hasCheckedRecurring.current = true;
  checkRecurring();
}

// Sub-collection onSnapshot
if (!hasCheckedRecurring.current && hasLoaded.current) {
  hasCheckedRecurring.current = true;
  checkRecurring();
}
```

Both handlers can trigger `checkRecurring()` — whichever fires second sees both flags are true and runs it once.

### Fix 2 — Dedup cleanup (`src/store/useFinanceStore.ts`)
Before the generation loop, deduplicates `transactions` by `recurringLinkId|date`:

```typescript
const deduped: Transaction[] = [];
const seen = new Set<string>();
for (const t of transactions) {
  const key = t.recurringLinkId ? `${t.recurringLinkId}|${t.date}` : t.id;
  if (!seen.has(key)) {
    seen.add(key);
    deduped.push(t);
  } else {
    hasCleanup = true;
  }
}
if (deduped.length !== transactions.length) {
  transactions = deduped;
}
```

Extra copies are dropped; `hasCleanup = true` triggers batch write that removes them from Firestore.
