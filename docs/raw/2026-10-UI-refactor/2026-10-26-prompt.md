# OpenCode Prompt: Redesign Transaction Ledger Implementation (React + Material UI)

## Context & Objective
We are implementing the complete redesign of the **Transaction Ledger & Records** page for **Balancr**.
A high-fidelity design prototype matching our approved Dashboard design system has been created in Google Stitch (`Screenshot 2026-10-26 alle 12.48.55.png`). The reference screenshot and exported HTML/Tailwind specifications are available in the project raw wiki sources.

Your goal is to reproduce this Transaction Ledger prototype in our React + Material UI (MUI v5) codebase with **95%+ visual and functional fidelity**, maintaining strict compatibility with our existing Zustand state management, TypeScript domain models, Day.js date handling, and Firebase backend.

---

## Technical Constraints & Design System Standards

1. **Strict MUI v5 Conversion (No Tailwind CSS)**:
   - Do NOT install or use Tailwind CSS in the project.
   - Convert all Tailwind classes to native MUI components (`Box`, `Grid`, `Stack`, `Paper`, `Card`, `Typography`, `Button`, `IconButton`, `Chip`, `Table`, `TableBody`, `TableCell`, `TableHead`, `TableRow`, `Select`, `TextField`) using `sx` props and themed custom components.
   - Map colors, spacing, and typography directly into our existing MUI theme (`createTheme` in `src/theme/`).

2. **Color Palette & Theme Tokens (Must match Dashboard)**:
   - **Background**: Deep Slate (`#0B0E14`)
   - **Card / Surface**: Solid Dark Slate (`#131B2E`) with a 1px solid subtle border (`#1E293B` or `#334155`).
   - **No Neon Background Glows / No Dot Patterns**: Keep surfaces flat, solid, and opaque.
   - **Accents**:
     - Cyan / Teal (`#0EA5E9` or `#06B6D4`): Active selections, filter chips & badges
     - Emerald Green (`#10B981`): Incomes / Positive cash flow (+€)
     - Coral Red (`#EF4444`): Expenses / Outflows (-€)
     - Amber (`#F59E0B`): Recurring expenses & alerts

3. **Typography & High-Density Table Precision**:
   - **Monospaced Numbers**: Use `JetBrains Mono` or `Roboto Mono` for ALL numerical values, currency figures (`€`), transaction IDs, and dates (`28 OTT 2026`).
   - **No Unwanted Text Wrapping**: Apply `noWrap` or `textOverflow: 'ellipsis'` on all table headers, KPI labels, and category names.
   - **Table Density**: Compact padding on table cells (`py: 1.5`, `px: 2`) for high information density.

4. **Component Architecture**:
   Structure the page under `src/pages/LedgerPage.tsx` and modular components under `src/components/ledger/`:
   - `LedgerPage.tsx`: Main view layout, inheriting `DashboardLayout` (collapsible 240px / 64px sidebar & topbar).
   - `LedgerSummaryCards.tsx`: 3 compact summary cards:
     * Inflow Period (`+€ 3.250,00` - Emerald)
     * Outflow Period (`-€ 1.840,20` - Coral Red)
     * Fixed Recurring Expenses (`-€ 620,00 / mo` - Amber)
   - `LedgerFilterToolbar.tsx`: Horizontal toolbar containing:
     * Date Range Picker (`Month`, `Quarter`, `Year`, `Custom`)
     * Category & Subcategory Filter Dropdown
     * Account / Card Filter Dropdown (`Intesa Private SDD`, `Conto Arancio ING`, `Carta Credito Gold`, `Degiro`, `Revolut`)
     * Transaction Type Filter (`All`, `Recurring`, `One-off`)
     * Clear Filters button & Active Filter Count
   - `TransactionTable.tsx`: Main data grid featuring:
     * Headers: `DATA` | `DESCRIZIONE & CATEGORIA` | `CONTO / METODO ADDEBITO` | `TIPO` | `IMPORTO` | `AZIONI`
     * Date formatted in Monospace
     * Category icon + Description subtitle (e.g., "Esselunga • Alimentari")
     * Payment Method Pill Badge with account icon
     * Type Badge (`Ricorrente Mensile`, `Bimestrale`, `PAC Automatico`, `Una Tantum`)
     * Amount aligned right in Monospace (+€ in Green, -€ in Red)
     * Action menu (Edit / Duplicate / Delete)
   - `NewTransactionModal.tsx`: Dialog / Drawer form for creating or editing transactions with recurring rule settings.

5. **State Management & Zustand Integration**:
   - Bind filters reactively to the transaction Zustand store (`src/store/useTransactionStore.ts`).
   - Support pagination or virtualized scrolling for large transaction sets.
